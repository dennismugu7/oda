# Decisions log

Append-only. Newest at the bottom. Format: date · decision · why · consequences.

1. **2026-09-30 · Payments: buyer pays the seller's own M-Pesa directly; the seller confirms by hand.** Why: matches the seller designs, zero fees while oda is free, no licensing exposure, fastest to build. Consequence: no STK push, no automatic confirmation or refunds in v1. The data model keeps `payment_method` extensible so an aggregator (STK push) can be added in v2.
2. **2026-09-30 · No deposits in v1.** Payment options are pay-before-delivery (full amount) and/or pay-on-delivery, per shop. Deposits → v2 (easier with an aggregator).
3. **2026-09-30 · No automated WhatsApp/SMS in v1.** WhatsApp actions open the seller's own WhatsApp with a pre-written message. Buyer tracking happens via the order link; optional buyer email. Seller alerts via Android push. Automated WhatsApp (Business Platform) → v2.
4. **2026-09-30 · Seller auth is email + password + 6-digit email code only.** No social login.
5. **2026-09-30 · Shop links live at `oda.mugu-labs.com/{slug}`.** The domain is a config value; old slugs/domains must redirect forever.
6. **2026-09-30 · Order links use a random token (`/o/{token}`)**, never the sequential order number.
7. **2026-09-30 · Products have no stock counts in v1.** Status only: Available / Sold out / Hidden. Optional was-price.
8. **2026-09-30 · Seller app is Android only; light theme only.**
9. **2026-09-30 · oda is free in v1.** No commission, no subscription.
10. **2026-09-30 · Stack:** pnpm + Turborepo monorepo; Expo (React Native, TypeScript, Expo Router) for the seller app; Next.js (App Router) + Tailwind for the buyer web + admin; Supabase (Postgres, Auth, Storage, pg_cron; no Edge Functions: server logic lives in Next.js API routes so it can share TypeScript with `packages/shared`); Resend for email; Expo push (FCM); Sentry; Vercel for web hosting; EAS for Android builds. Why: one language (TypeScript) end to end, generous free tiers, well supported by Claude Code. Keep the web app host-agnostic (no Vercel-only APIs).
11. **2026-09-30 · Environments:** local (Docker Postgres) → staging (Neon project + R2 bucket + preview web) → production.
12. **2026-09-30 · Buyer favourites are stored on the device only.**
13. **2026-09-30 · Server logic lives in Next.js API routes.** Order mutations go through `transitionOrder()`: a conditional UPDATE on the expected-from status inside a transaction (race-safe). The Expo app uses the same API.
14. **2026-09-30 · Image sizes are generated on the device** (full ~1600px + thumbnail ~400px). No paid image-transformation service.
15. **2026-09-30 · A payment claim is not money.** Cancelling a claimed order asks the seller whether the money arrived before creating a refund.

28. **2026-10-01 · Windows Android builds use ninja 1.12+ (long-path aware) inside the SDK's CMake 3.22.1.** Why: native modules compile inside pnpm's store, where paths reach 280 characters (e.g. `react-native-worklets/android/.cxx/…/ReactAndroidConfigVersion.cmake`). The ninja 1.10.2 bundled with SDK CMake 3.22.1 can't see paths over 260 even with Windows long paths enabled, so it looped (`build.ninja still dirty after 100 tries`). Rejected: lowering pnpm's `virtualStoreDirMaxLength` (its floor of `_` + 32-char hash only gets to 253); relocating each module's `.cxx` folder (Worklets hard-codes `${projectDir}/.cxx` in its prefab/PCH scripts); moving the repo to `C:\oda` (257, too close). Setup (once per Windows machine): `sdkmanager "cmake;3.31.6"`, then copy its `bin\ninja.exe` over `cmake\3.22.1\bin\ninja.exe` (old one kept as `ninja-1.10.2.exe`). Consequences: no repo code, no effect on CI/Linux/EAS; must be redone if the SDK's CMake 3.22.1 is reinstalled.

33. **2026-10-01 · Input rules in `packages/shared` (M1).** **M-Pesa code** (owner-approved): 10 characters `A–Z`/`0–9` starting with a letter, case-insensitive; **no digit required**, because real codes are random and about 5% are all letters. In a pasted SMS, the token right before "Confirmed" wins, otherwise the first match. Why: a false accept is harmless (the seller confirms by hand), a false reject blocks a paying buyer. **Slugs:** spec rules (`a-z0-9-`, 3–30, reserved list) plus no leading, trailing or double hyphens; names are slugified with accents folded and `&` → "and". **Phones:** Kenyan mobiles only (`+2547…` / `+2541…`), input with `07…`, `01…`, `7…`, `1…`, `254…`, `+254…` and spaces/dashes/dots/brackets. **Quantities:** 1–99 per line.
34. **2026-10-01 · M1 schema refinements to `data-model.md`** (migrations `0001_schema`, `0002_triggers`). (a) **Better Auth tables are `auth_user`, `auth_session`, `auth_account`, `auth_verification`** with uuid ids (`user` is reserved in Postgres; owner-approved); `profiles.id` references `auth_user.id`. A missing profile is created on first use (idempotent). (b) **`orders.awaiting_payment_since`**: set when an order (re-)enters `awaiting_payment`; the 48h auto-expire counts from it, so "payment not found" gives the buyer a fresh 48h (owner-approved). (c) Primary keys the doc left implicit: `review_items (review_id, order_item_id)`, `shop_visits_daily (shop_id, day, source)`, `rate_limits (key, window_start)`, `order_events.id`. `review_items.rating` is nullable (an item can be left unrated). (e) **Database guards:** a trigger rejects any UPDATE of `orders.status`/`payment_status` unless the transaction set `oda.transition = 'on'`, which only `transitionOrder()` does; slug triggers move old slugs to `shop_slug_history` automatically, let the owner reclaim their own, and refuse another shop's live or historical slug. (h) Product search: GIN expression index with the `simple` text-search config (mixed English/Swahili). (i) `rate_limit_hit(key, window_seconds, max)` fixed-window SQL function. (j) Checks: pay-before or pay-on-delivery on; one active payment account; paybill reference rules; was-price > price; `total = subtotal + delivery_fee`; qty 1–99; ratings 1–5; pickup orders have no delivery area; onboarding step 3–6.
